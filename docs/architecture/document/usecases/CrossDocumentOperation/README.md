# Overview: Business Background for Cross Document Creation

The **Cross Document Creation** process addresses business scenarios where a new target document is generated by leveraging multiple selected items from a source (current) document.
This functionality is particularly utilized for creating a new target document item list derived from the selected items of the source document.
---

## Key Features

The Cross Document Creation functionality offers **two main features** supported by APIs to facilitate its operations:

### 1. Cross Document Creation Execution
This feature focuses on the execution of the Cross Document Creation process. 
It enables the creation of a new target document based on selected items from the source document and ensures that the newly created items are stored in a persistent database.

### 2. Loading an Existing Target Document
This feature allows end-users to either create an entirely new target document or associate the newly created items with an existing 
target document's root node. Users can load and select the appropriate existing target document root node before executing the creation process for seamless integration.

---

## Use Cases

The Cross Document Creation process caters to **four distinct use cases**, each addressing specific business scenarios:

### Use Case 1: Creating a Standard Previous-Next Document Relationship
- **Description:** This use case establishes a basic previous-next relationship between the source and target documents. 
A new target document is created based on the current document, with the two documents linked directly in order.
- **Example:** Generating a warehouse inbound delivery document based on a selected purchase contract. 
This occurs when the purchased materials mentioned in the contract are delivered and ready for storage in the warehouse.
- **Detailed Documentation:** [Creating Previous-Next Document Relationship](#)

---

### Use Case 2: Creating from a Professional Previous-Next Document Relationship
- **Description:** In this scenario, a professional previous-next document relationship is built, where an additional "professional previous document" 
is identified along with the standard source document during the creation process.
- **Example:** Generating a purchase return order. If the purchased materials are stored in a warehouse, the warehouse storage 
item becomes the direct previous document, while the original purchase contract is the professional previous document.
- **Detailed Documentation:** [Cross Document Creation From Previous](CrossDocCreationPrevious.md)

---

### Use Case 3: Creating to a Professional Previous-Next Document Relationship
- **Description:** This use case involves creating a direct previous-next relationship between the source and target documents
while identifying a "professional previous document" for inclusion in the document relationship.
- **Example:** Generating a purchase return order with the warehouse storage item as the standard source document and the 
original purchase contract identified as the professional previous document.
- **Detailed Documentation:** [Cross Document Creation From Professional Previous](CrossDocCreationFromProfPrev.md)

---

### Use Case 4: Creating a Reserved Document Relationship
- **Description:** This use case involves reserving a resource document as the basis for generating the target document. 
The target document is created based on the reserved document while maintaining a direct previous-next relationship.
- **Example:** When a sales contract leads to the creation of an outbound delivery, the system reserves available resources 
(e.g., warehouse inventory) and generates the outbound delivery with a documented link to the reserved resource.
- **Detailed Documentation:** [Cross Document Creation To Professional Previous](CrossDocCreationToProfPrev.md)

---

## Framework Overview and Workflow

Though each of the above use cases has unique nuances, they follow a **universal framework** with similar process steps. 
Any variations in logic are handled through configurable properties and custom callback steps.

**Detailed Documentation:** [Cross Document Creation With Reservation](CrossDocCreationReserve.md)

### Universal Workflow for Cross Document Creation
The core workflow for Cross Document Creation consists of the following steps:

#### 1. Load Existing Target Document Root Node
- The system retrieves the existing target document's root node to verify if it can accommodate the newly created items.

#### 2. Traverse Source Document Items
- The key logic centers on traversing the material item list in the source document and executing essential actions, such as creating target document items and retrieving relevant resources.

#### 3. Create a New Target Document Root Node
- During traversal, the system creates a new target document root node if none exists and stores it in the **Document Creation Context**.

#### 4. Generate Target Document Items
- For each selected source item, the system creates a corresponding target document item. During this step, relevant resources or data transformations (e.g., mapping properties) are applied, 
- and the data is stored in the **Document Creation Context**.

#### 5. Persist New and Updated Documents
- After processing all selected items, the system persists the newly created target document, along with other components such as the root node, material item nodes, and any associated data (e.g., attachments).
- Additionally, updates to the source document (if applicable) are also saved in the persistence layer.
